# Tracker Panel official Instagram + Facebook backend

## Architecture and scope
`lib/lume-server.mjs` and `lib/backend/*.mjs` vendor the production Lume backend from `/root/instagram-metrics-app` as an in-process engine. `lib/metrics-integration.js` mounts its native HTTP request listener in Express under `/api/metrics/*` and `/auth/*`; no listener, HTTP proxy, shared Basic credential forwarding, or dependency on the existing Lume deployment is used. Production Lume files/accounts/data were not changed. Use **one Node process per DATA_DIR**.

Includes provider-separated Instagram/Facebook OAuth, one-use expiring browser state, encrypted SQLite personal workspace, encrypted account/token/diagnostic/cache records, long/short token lifecycle, Page-only token persistence, bounded provider calls, period snapshots and exact-range stale fallback, today attribution guard, media-detail ownership/budgets/cache, sanitized diagnostics, CSRF, rate limits and in-flight request reuse. CSV is generated by the Tracker UI from these payloads; there is no separate backend export route.

`METRICS_CONTRACT.md` defines the browser contract. Real provider failures stay errors/null, not fabricated zero/demo data. Facebook advanced media details and organic per-video country attribution remain explicitly unsupported; today remains unavailable unless intraday attribution is verifiable.

## Runtime prerequisite (IMPORTANT)
Use **Node >=22.13** (tested 22.22.1), including in Docker. The Dockerfile now uses `node:22-slim`, and package.json declares the minimum version. Rebuild existing Node 20 containers before enabling metrics: `node:sqlite` is unavailable there. No npm dependency is needed for this engine. The native SQLite experimental warning on Node 22 is expected.

## Configure a NEW Tracker deployment
1. Choose Tracker's own HTTPS origin, e.g. `https://tracker.example.com`. No trailing slash/path in `PUBLIC_BASE_URL`. Put a TLS reverse proxy in front; never expose Basic auth over public HTTP. Preserve Authorization and Origin headers. Do not log them.
2. Create two private writable directories owned by the app service user: `/var/lib/tracker-metrics` (0700, new encrypted store) and `/var/lib/tracker-panel` (legacy tracker account JSON). **Never point DATA_DIR at the running Lume store or import/copy its accounts without explicit authorization.** Repository-local DATA_DIR is rejected.
3. Copy `.env.metrics.example` to a private file outside the checkout (e.g. `/etc/tracker-panel/metrics.env`), mode 0600. Set `METRICS_ENABLED=true`, `METRICS_USERNAME` and a long unique `METRICS_PASSWORD`; missing either returns 503 for the **entire panel**, including its root document, legacy APIs, assets and callbacks. Set provider app credentials on the server only. Instagram Login credentials and Facebook Login credentials are separate.
4. Generate a key with `node -p "require('node:crypto').randomBytes(32).toString('hex')"` and privately store it as `TOKEN_ENCRYPTION_KEY`. Back up the key and encrypted data together securely. Losing/rotating it makes stored accounts unreadable. App-secret rotation must NOT rotate this key.
5. Register these exact OAuth redirect URIs in the relevant provider apps, replacing only the example hostname with YOUR configured Tracker hostname:
   - Instagram Login: `https://tracker.example.com/auth/instagram/callback`
   - Facebook Login: `https://tracker.example.com/auth/facebook/callback`
   Configure the authorized website domain and required provider permissions/review/tester roles too. Existing Lume redirect registration does not automatically authorize Tracker.
6. Start with `node --env-file=/etc/tracker-panel/metrics.env server.js`. Existing `PORT`, `HOST`, `DB_PATH`, Chromium and yt-dlp configuration is preserved. Container deployments mount env privately and mount the new DATA_DIR outside `/app`; set HOST=0.0.0.0 on a private network, not a public unauthenticated port.
7. Visit `https://tracker.example.com/auth/login`. The browser-native HTTP Basic prompt handles credentials; JavaScript does not read, send, or persist passwords/tokens. Same-origin metrics fetches use native browser authentication. Then navigate `/api/metrics/auth/start?provider=instagram` or `provider=facebook` and complete official consent yourself.
8. Check authenticated `/api/metrics/config`, then `/api/metrics/accounts`, `/api/metrics/dashboard?provider=instagram&account=all&days=7` and the Facebook equivalent. Configuration or a mocked OAuth test is NOT proof of real authorization/permissions/data. Verify both real callbacks/consents after deployment; no real Tracker domain/deployment was supplied during implementation.

## Private runtime app-credential reference (local filesystem only)

Set `METRICS_SECRETS_FILE=/root/.hermes/secrets/tracker-panel-meta.json` in the
**server's** deployment environment to load app configuration at startup. Nothing
is fetched by the browser, from an HTTP endpoint, or from a public/private bucket.
The reference is a path, not a credential. The local private file is not in Git or
the Docker build context. There is no implicit default path or automatic remote wiring.

The JSON object allows **only** `META_APP_ID`, `META_APP_SECRET`, `FACEBOOK_APP_ID`,
and `FACEBOOK_APP_SECRET`, with nonempty string values. A nonempty subset is allowed
for single-provider deployments; all four are provisioned in the local test file.
Do not add access tokens, accounts, passwords, or an encryption key. Tracker must
still have its own access password, encryption key, and fresh data directory; do not
load the original Lume env file into Tracker or share its account store.

The server loads this file before integration and whole-panel security snapshots.
Explicit environment variables take precedence **even when empty**: remove/comment
the four app-variable assignments in your env file to use JSON values. The entire
JSON file is validated first, even if all four variables are already set. Invalid
configuration stops startup with `Invalid metrics secrets configuration`, without
logging file paths, parser contents, or secret values. An absent reference preserves
existing env-only behavior; an explicitly empty reference is invalid.

Requirements: absolute path; resolved realpath outside the checkout; regular file,
single hard link, owned by the service UID, mode **0600 or 0400**; immediate resolved
parent owned by that UID with mode **0700**; valid UTF-8 JSON at most **16 KiB**.
The loader never repairs permissions. Do not chmod an existing shared directory to
make this work: use an already-private directory or create a dedicated one. Keep
ancestors under trusted administrative control; the service user/root must be trusted.
Changes are read on process startup only; restart Tracker after private rotation.
Never print the JSON, inspect expanded deployment configuration in logs, or put real
values into shell arguments, tracked examples, screenshots, or frontend storage.

### Docker read-only reference

The Dockerfile creates `/run/secrets` as 0700. Add the following **reference-only
fragment to your actual Tracker service** in its private deployment configuration:

```yaml
services:
  tracker:
    environment:
      METRICS_SECRETS_FILE: /run/secrets/tracker-meta.json
    volumes:
      - type: bind
        source: /root/.hermes/secrets/tracker-panel-meta.json
        target: /run/secrets/tracker-meta.json
        read_only: true
        bind:
          create_host_path: false
```

This is not a complete deployment: retain the separate private access/key config,
new writable data mounts and TLS/private-network settings above. The mount source
must exist on the **Docker host**; a file on this machine does not configure a remote
host. The current image runs as root; if changing its UID, provision a dedicated
private file and `/run/secrets` directory owned by that service UID rather than
loosening permissions. Do not COPY secrets into an image or use default world-readable
Docker secret-file permissions. Recreate the container after replacing a bind-mounted
file atomically so it mounts the new inode.

No actual Tracker hostname has been supplied. Set the real `PUBLIC_BASE_URL` and
register its two callbacks with Meta before user consent. File loading proves only
local configuration, not app validity, provider permissions, OAuth, or deployment.

## Compatibility/security changes
- Existing other-platform CRUD/folders/fetch routes are retained, not silently migrated.
- Source-directory static serving is replaced by a small public-asset allowlist. `/accounts.json`, `/server.js`, `/.env`, `/lib/*`, `.git` and dependencies cannot be downloaded.
- Old `/api/settings/{instagram,facebook}-token` write/read routes and `/api/instagram/available-accounts` return 410 `use_metrics_oauth`; no new plaintext provider tokens can be entered there. Existing plaintext `_settings` is excluded from `/api/accounts`; private platform keys are rejected. Legacy Instagram collection now returns 410 with an OAuth entry point, and account creation never consumes old tokens. Legacy Facebook collection retains public scraping, not plaintext Graph-token access. All legacy JSON and streamed fetch results recursively redact credential fields; cookie updates remain write-only. Legacy HTML escapes stored names/handles/content/attributes and permits only HTTP(S) media URLs. Historical on-disk values are NOT migrated or deleted automatically. Remove old plaintext credentials from a private backup/restored database and rotate them as a separate authorized maintenance step.
- **Whole-panel authentication is mandatory for deployment.** The same Basic gate runs before every route and asset whenever `METRICS_ENABLED=true` or any metrics credential/provider/store setting is present. Partial credentials fail closed for the whole origin. There is no metrics-only authentication option: legacy stored content shares the authenticated origin. With every metrics setting absent, local legacy-only compatibility remains unauthenticated; never publish that mode. The example explicitly enables fail-closed mode. No provider token is placed into frontend storage.
- All authenticated state-changing requests (legacy POST/PATCH/PUT/DELETE as well as metrics sync/disconnect) require Origin exactly equal to PUBLIC_BASE_URL; missing or cross-origin requests return 403. Missing/invalid PUBLIC_BASE_URL blocks writes with 503. Configured mode sends no permissive CORS headers. CLI clients must supply Basic auth and that exact Origin. Do not manually set Origin in browser JS; the browser sends it. Disconnect deletes local connections, not provider permission grants. `account=all` affects all providers.

## Verification
Run `npm test` (or backend-only `node --test tests/backend-integration.test.mjs tests/panel-security.test.mjs tests/backend-lume/*.test.mjs`). Suites use temporary stores, explicit provider mocks and random loopback ports. They cover native engine behavior plus the Express mount, authentication/failclosed/CSRF, Tracker callbacks, encrypted storage, filters, stale-cache/empty/null semantics, media ownership, today guards, private-file denial and legacy other-platform CRUD. No live provider tokens/accounts are used. Public HTTPS, provider consent and actual data validation remain deployment acceptance steps.
